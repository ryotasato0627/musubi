# ドキュメント執筆のルール

- 日本語で書く。文体は「〜する」「〜である」の常体
- 役割を分ける：`docs/spec/` は仕様、`docs/adr/` は設計判断の記録、`docs/plans/` は実装計画。仕様のうち requirements.md は「何を・なぜ」、design.md は「どう実現するか」。design.md は要件 ID（`F-xx` / `NFR-xx` / `E/W/Ixxx`）を引いて書く
- ID は振り直さない。廃止するときは欠番にする
- 設計判断は `adr-writer` Skill で ADR（`docs/adr/NNNN-<slug>.md`）に記録し、design.md 12 章の表には 1 行の要約と ADR へのリンクを書く（見出し下の日付も更新する）
- `承認` の ADR は書き換えない。判断を変えるときは新しい ADR で置き換える
- 未確定の事項は「（要確認）」と明記する
- 不採用にした案は、理由とあわせて短く残す

## README

- README は人間向け、`CLAUDE.md` と `.claude/rules/` は Claude 向け。互いに本文を写さず、リンクする
- フォルダーの階層で読み手を分ける。ルートは利用者、`docs/` は仕様を読む人、`docs/adr/` は判断の経緯を追う人、`docs/plans/` は計画を承認する人、`.claude/` は開発フローを使う・保守する人
- 冒頭に `> 対象読者：` と `> 次に読むもの：` を書く
- 本文はそのフォルダーの地図にとどめ、下の階層の内容を写さずリンクする
- まだ存在しないファイルを、あるものとして書かない（予定なら「予定」と書く）
- `.claude/skills/` の中には README を置かない（musubi の探索対象のため）。Go のパッケージには README ではなく `doc.go` を書く
