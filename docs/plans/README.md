## 人間が判断するところ

1. **計画の承認**：`/release-plan <版>` が出す計画を確認して承認する。未決定事項はこの時点で選ぶ
2. **PR のレビュー**：`/dev-cycle` が作った PR を GitHub 上でレビューする。「人間に判断してほしい点」には `D1: 案 A` のように ID で答える

それ以外の工程は止まらずに進む。手順の詳細は [.claude/README.md](../../.claude/README.md)。

## 計画と PR の状態

- 計画：`承認済み` ⇄ `要見直し`。次のどれかで `要見直し` になり、`/release-plan update <版>` で見直すまで次の PR は始まらない
  - 実績行数が見込みの 1.5 倍を超えた
  - 修正上限に達して Draft PR になった
  - レビューでの判断で、後続の PR の範囲や設計が変わった
  - 「次の候補（範囲外の指摘から）」が 5 件を超えた
- PR：`未着手` → `開発中` → `PR作成済` / `Draft` → `マージ済`（`中止` もあり）
